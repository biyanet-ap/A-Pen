### 1.3 페이지 데이터의 현재 모습 (바꿔야 할 핵심)

페이지가 배열 3칸으로 고정돼 있고, 인덱스는 `board` 값(0=화면, 1=흰 칠판, 2=검은 칠판)입니다.

```
OverlayWindow.Pages[3]     : StrokeCollection   (필기)
OverlayWindow.Bubbles[3]   : List<UIElement>    (말풍선)
ToolbarWindow.history[3]   : List<InkEdit>      (되돌리기 기록)
ToolbarWindow.shownBoard   : 지금 캔버스에 붙어 있는 페이지 번호
```

`board` 하나로 "어느 칠판인지"와 "어느 페이지인지"를 동시에 나타내고 있어서, 칠판마다 페이지를 여러 개 두려면 이 셋을 **페이지 객체 하나로 묶어야** 합니다.

## 2. 설계

### 2.1 데이터 모델

```csharp
// 페이지 하나 = 필기 + 말풍선 + 되돌리기 기록 + (있으면) 배경 이미지
class Page
{
    public StrokeCollection Strokes = new StrokeCollection();
    public List<UIElement> Bubbles = new List<UIElement>();
    public List<InkEdit> History = new List<InkEdit>();
    public ImageSource Image; // 불러온 스크린샷. 없으면 null
}
```

| 위치 | 변경 전 | 변경 후 |
|---|---|---|
| `OverlayWindow` | `Pages[3]`, `Bubbles[3]` | `Page Screen` + `List<Page>[] Boards` (0=흰, 1=검) |
| `ToolbarWindow` | `history[3]`, `shownBoard` | `int[] pageIndex` (칠판별 현재 페이지), `Page shownPage` |
| `ToolbarWindow` | — | `Page Cur` 속성: `board == 0 ? Screen : Boards[board-1][pageIndex[board-1]]` |

- `InkEdit` 클래스는 `ToolbarWindow` 안에서 밖으로 꺼내 `Page`가 참조할 수 있게 합니다(내용은 그대로).
- 되돌리기 기록(`RecordInkEdit`)은 지금처럼 `StrokesChanged` 이벤트로 받되, **페이지를 만들 때** 그 페이지의 `Strokes`에 구독합니다.
- 화면(board 0)은 지금처럼 페이지 1개만 둡니다.

### 2.2 기능 3 — 칠판 여러 페이지

**동작**

| 동작 | 버튼 | 단축키 | 설명 |
|---|---|---|---|
| 이전 페이지 | ◀ | Ctrl+Alt+PageUp | 첫 페이지면 아무 일 없음 |
| 다음 페이지 | ▶ | Ctrl+Alt+PageDown | 마지막 페이지면 아무 일 없음 |
| 새 페이지 | ＋ | Ctrl+Alt+N | 현재 페이지 **바로 뒤**에 빈 페이지를 넣고 그 페이지로 이동 |
| 페이지 삭제 | 🗑 | 없음 | 현재 페이지를 지움. 아래 규칙 참고 |

**페이지 삭제 규칙**

| 상황 | 동작 |
|---|---|
| 페이지에 필기·말풍선·배경 이미지가 있음 | "이 페이지를 삭제할까요?" 확인 창(예/아니요)을 띄운 뒤 삭제 |
| 빈 페이지 | 확인 없이 바로 삭제 |
| 삭제 후 이동 | 다음 페이지로. 마지막 페이지를 지웠으면 그 앞 페이지로 |
| 페이지가 1장뿐일 때 | 그 페이지를 비워서(필기·말풍선·배경 이미지·되돌리기 기록 모두) 빈 페이지 1장으로 남김. 칠판에는 항상 최소 1장 |
| 되돌리기 | 페이지 삭제는 되돌릴 수 없음 (그래서 확인 창을 둠) |

> 단축키를 두지 않는 이유: 되돌릴 수 없는 동작이라 강의 중 잘못 눌리는 것을 막기 위해서입니다. Ctrl+Alt+Delete는 Windows가 예약해 둔 키라 쓸 수도 없습니다.
> 확인 창은 툴바를 주인으로 띄워 칠판 위에 보이게 합니다.

- 단축키는 칠판이 켜져 있을 때만 동작합니다(화면 모드에서는 무시).
- 칠판을 껐다 켜도 마지막으로 보던 페이지로 돌아옵니다.
- 지우기(Clear)·되돌리기(Undo)는 **현재 페이지에만** 적용됩니다(지금 규칙과 같음).

**툴바 UI**: 칠판 버튼 바로 아래에, 칠판이 켜져 있을 때만 보이는 한 줄을 추가합니다.

```
┌──────────────┐
│   ▭ 흰 칠판   │
├──────────────┤
│  ◀   2/5   ▶  │  ← 칠판 켜졌을 때만 표시 (툴바 폭 84px)
│   ＋    │  🗑  │  ← 새 페이지 / 페이지 삭제
├──────────────┤
│   ↶ 되돌리기  │
```

> Ctrl+Alt+←/→ 를 쓰지 않는 이유: Intel 그래픽 드라이버가 많은 PC에서 Ctrl+Alt+방향키를 **화면 회전**에 쓰고 있어 충돌합니다.

### 2.3 기능 1 — 스크린샷 저장

| 항목 | 내용 |
|---|---|
| 버튼/단축키 | 툴바에 "캡처" 버튼, **Ctrl+Alt+K** (C는 지우기가 이미 사용) |
| 찍는 범위 | 설정에서 고른 모니터 영역 전체 (`Native.GetScreen(cfg.Monitor).Bounds`, 물리 픽셀) |
| 찍는 방법 | Win32 `GetDC(NULL)` + `BitBlt(SRCCOPY \| CAPTUREBLT)` — 투명 필기 창(레이어드 창)도 함께 찍힘. ※ `Graphics.CopyFromScreen`은 두 값을 합친 인자를 받지 않아(`InvalidEnumArgumentException`) 쓰지 않음 |
| 빼고 찍기 | 찍기 직전 툴바·스팟·정보 창을 잠깐 숨기고(투명도 0), 화면에 반영된 뒤 찍고 바로 복원 |
| 확대 중 | 확대된 모습 그대로 찍힘 ("보이는 화면 그대로" 원칙) |
| 저장 | `Environment.SpecialFolder.DesktopDirectory` + `HighPen_yyyyMMdd_HHmmss.png`. 같은 초에 또 찍으면 `_2`, `_3` 붙임 |
| 성공 표시 | 캡처 버튼이 0.5초간 강조색으로 깜박임 |
| 실패 처리 | 저장 실패(권한·디스크 등 `IOException`/`UnauthorizedAccessException`)면 메시지 상자로 알림. 그 외 예외는 잡지 않음 |

**숨김 → 찍기 → 복원 순서**

```
1. toolbar.Opacity = 0, spot 숨김, aboutWin.Opacity = 0
2. Dispatcher.BeginInvoke(..., DispatcherPriority.ContextIdle)  ← WPF 렌더링이 끝난 뒤
   + 약 50ms 지연(DispatcherTimer 1회)                          ← DWM이 화면에 반영할 시간
3. CopyFromScreen → PNG 저장
4. finally 블록에서 투명도·스팟 복원
```

> 대안으로 검토한 것: `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`로 툴바·스팟을 캡처에서 빼면 깜박임이 없지만, **Zoom·Teams 화면 공유에서도 스팟이 사라져** 이 앱의 핵심 기능이 망가집니다. 그래서 채택하지 않습니다.

### 2.4 기능 2 — 스크린샷 불러오기

| 항목 | 내용 |
|---|---|
| 버튼/단축키 | 툴바에 "불러오기" 버튼, **Ctrl+Alt+O** |
| 파일 선택 | Windows 기본 파일 열기 창(`Microsoft.Win32.OpenFileDialog`), 시작 폴더 = 바탕화면, 필터 `HighPen_*.png` / 모든 이미지(png, jpg, bmp) |
| 결과 | 칠판이 꺼져 있으면 **흰 칠판**을 켜고, 켜져 있으면 지금 칠판에서, 현재 페이지 바로 뒤에 새 페이지를 만들어 이미지를 배경으로 깔고 그 페이지로 이동. 펜 모드 켬 |
| 그리기 | `InkCanvas.Background = new ImageBrush(img) { Stretch = Uniform }`. 창 배경은 칠판색 그대로라 비율이 다르면 위아래/좌우 여백이 칠판색으로 보임 |
| 파일 잠금 | `BitmapImage` + `CacheOption = OnLoad`로 읽고 바로 파일을 놓아줌 (바탕화면 파일 삭제·이동 가능) |
| 지우기 | 지우기(Clear)는 필기·말풍선만 지우고 **배경 이미지는 남김** |
| 실패 처리 | 이미지가 아니거나 읽을 수 없으면 메시지 상자로 알림 |

> 파일 열기 창은 툴바를 주인(Owner)으로 띄워 항상 툴바 위에 오게 합니다. 툴바가 주기적으로 최상위를 다시 잡는(`ReassertTop`) 구조라 실제 PC에서 창이 가려지지 않는지 꼭 확인해야 합니다(검증 항목 4-3).

### 2.6.1 추가 요구사항 — 녹색 칠판 (2026-10-20)

| 항목 | 결정 |
|---|---|
| 순환 순서 (B 버튼 / Ctrl+Alt+B) | **녹색 → 흰색 → 검정 → 끄기** |
| 녹색 | `#2E5B3C` (보통 칠판 녹색) |
| 펜 색 자동 전환 | 녹색 칠판을 켤 때 펜이 검정 또는 초록(`#34C759`)이면 흰색으로. 흰/검은 칠판 규칙은 그대로 |
| 페이지 | 녹색 칠판도 자기 페이지 목록을 따로 가짐 (이동·추가·삭제·불러오기 모두 동일) |

**내부 표현**: 기존 번호를 바꾸지 않고 `board = 3`을 녹색으로 추가합니다. 순서는 번호 대신 다음 칠판 표로 정합니다.

```csharp
// 현재 칠판 번호 → 다음 칠판 번호. 끄기(0)→녹(3)→흰(1)→검(2)→끄기(0)
static readonly int[] NextBoard = { 3, 2, 0, 1 }; // [0]끄기→3녹, [1]흰→2검, [2]검→0끄기, [3]녹→1흰
```

| 위치 | 변경 |
|---|---|
| `OverlayWindow.Boards` | 페이지 목록 2개 → 3개 (`Boards[2]` = 녹색) |
| `pageIndex` | `{0,0}` → `{0,0,0}` |
| `CycleBoard` | `(board+1)%3` → `NextBoard[board]`, 녹색 펜 자동 전환 규칙 추가 |
| `ApplyMode` | 배경 `board == 3` → `#2E5B3C`, 버튼 이름을 표(`BoardNames`)로 |
| `Lang` | `GreenBoard`(녹색 칠판 / 緑ボード / Green) 추가, `BoardTip`을 녹/흰/검/끄기로 |
| README 3개 | 칠판 순서·설명·펜 자동 전환 문구. 녹색 칠판 스크린샷 이미지는 없음(추가하려면 `screen/`에 넣어야 함) |

**영향받는 기존 결정**: 스크린샷 불러오기는 "칠판이 꺼져 있으면 **흰 칠판**을 켠다"였으나, B 한 번 누른 것과 같게 **녹색 칠판**을 켜는 것으로 변경 확정(사용자 결정 (가)). 코드는 그대로 `CycleBoard()` 사용.

예상 변경량: `HighPen.cs` 약 10줄.

### 2.6.3 추가 요구사항 — 부분 지우개, 지우개 크기 (2026-10-21)

**배경**: 지우개가 `EraseByStroke`(획 단위)라서 선의 일부만 문질러도 선 전체가 지워짐 → 칠판 지우개처럼 문지른 부분만 지우고 크기를 고를 수 있게.

| 항목 | 결정 |
|---|---|
| 방식 | `InkCanvasEditingMode.EraseByPoint`(부분 지우기)로 교체. 획 단위 지우기는 없앰 |
| 와콤 지우개 끝 | `EditingModeInverted = EraseByPoint` (기본값이 획 단위라 함께 바꿔야 동작이 같아짐) |
| 모양 | 사각형, 가로:세로 = 2:1 → `new RectangleStylusShape(크기, 크기 / 2)` |
| 크기 | 설정 패널 "지우개 크기" 슬라이더 10~150, 기본 40 (가로 기준, DIP). `settings.txt`에 `EraserSize`로 저장. 파일 값이 범위를 벗어나면 10~150으로 맞춤 |
| 커서 | 지우개일 때 `UseCustomCursor = false` → WPF가 지우개 모양·크기 그대로 커서를 그림(`GetPointEraserCursor`). 지금은 십자 커서로 강제하고 있어 크기가 안 보임 |
| 되돌리기 | 부분 지우기는 선을 조각으로 나눔(원래 선 삭제 + 조각 추가가 한 이벤트로 옴). 기존 `RecordInkEdit`가 한 번 문지르기 동안의 추가·삭제를 한 단계로 모으고, 조각을 다시 지우면 추가 목록에서 빼므로 그대로 동작 |
| 그대로 두는 것 | 지우개 상태에서 Ctrl+Alt+E 한 번 더 = 페이지 전체 지우기, 지우기(Ctrl+Alt+C) 버튼, 말풍선과 불러온 배경 이미지는 지우개로 지워지지 않음 |

**확인 필요(실기)**: 지우개 크기가 커도(150) 커서가 제 크기로 보이는지, 확대 중에도 커서와 실제 지우는 범위가 맞는지, 지우개 상태에서 슬라이더를 움직이면 커서 크기도 바로 바뀌는지.

**커서 갱신**: WPF는 `EraserShape`를 바꿔도 편집 모드가 바뀔 때까지 지우개 커서를 다시 그리지 않음(문서의 주의 사항). 그래서 `ApplyPen`에서 지우개 상태면 `EditingMode`를 `None` → `EraseByPoint`로 한 번 바꿨다 돌림.

예상 변경량: `HighPen.cs` 약 15줄.

### 2.6.4 추가 요구사항 — 영역 지우기 (드래그한 사각형 안을 지움) (2026-10-21)

| 영역 | 지우개(문지르기) | 끄기(펜) | 지우개(문지르기) |

| 위치 | 변경 |
